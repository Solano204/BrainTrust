# Git Commit Best Practices

## Basic Rules

### Commit Related Changes
A commit should be a wrapper for related changes.

### Commit Often  
Committing often keeps your commits small.

### Don't Commit Half-Done Work
You should only commit code when a logical component is completed.

### Test Your Code Before You Commit
Test it thoroughly to make sure it really is completed.

### Write Good Commit Messages
Begin with a short summary (50 chars or less).

## Formatting Rules
- Capitalized, short summary
- Blank second line  
- Write in imperative mood
- Wrap body to 72 characters
- Use bullet points
